]]].What is SIP.js ?
=> As per my understanding, SIP.js is a JavaScript library which is used to implement SIP functionality in our application. SIP stands for Session Initiation Protocol, and it is mainly used for call signaling and managing the call session in the browser.
In my project, I worked on the SIP.js library, and I handled how dynamic SIP headers are passed to the FreeSWITCH server. When the agent clicks on the call button, first the INVITE request is sent to the FreeSWITCH server through SIP.js.
After sending the INVITE, I receive the 100 status code, which means Trying. After that, I receive 180 Ringing when the customer side is ringing, and sometimes 183 Session Progress. Then, when the customer accepts the call, I receive 200 OK, and after that the call is connected between the agent and customer.
In this flow, I also worked on dynamic headers. We pass multiple types of information through these headers, like call direction, URI, campaign, process, agent information, customer or lead information, list information, callback information, and agent DID number.
These dynamic headers are passed in the SIP INVITE request using SIP.js extraHeaders. FreeSWITCH receives these headers and can use this information for call routing, campaign processing, lead tracking, and reporting.
So basically, SIP.js is handling the SIP signaling part in our Angular application, FreeSWITCH is handling the SIP server-side call processing, and WebRTC is handling the actual audio communication between the agent and customer.

]]].What is NGINX ?
→ Nginx is a reverse proxy.
→ It is also used to serve the Angular static files like HTML, CSS, JavaScript, and images.
→ Nginx also provides an additional layer of security. That means, instead of the client directly accessing the backend server, the client request first comes to Nginx. So the client does not directly access the backend server.
→ Then Nginx decides where this request should be sent based on the configuration.
→ In my current application, we use Nginx as a load balancer also. We use the default Round Robin algorithm, where requests are sent one by one to the available backend servers.
→ For example, the first request goes to Server 1, the second request goes to Server 2, and the third request goes to Server 3, and then it starts again from Server 1.
→ So, the requests are distributed across multiple servers instead of putting all the load on a single server.
→ Overall, Nginx is used in our application for serving Angular files, reverse proxying, and load balancing.

Observable vs Promise?
👉 Observable is a feature of RxJS library, while Promise is a core JavaScript object.
👉 Both are used to handle asynchronous operations in Angular applications.
👉 Promise handles only one value and cannot be cancelled or unsubscribed once started.
👉 Observable can handle multiple values over time and can be unsubscribed to stop the data stream.
👉 Promise has three states: Pending, Resolved, and Rejected.but Observable does not have predefined states like Promise.

Every request first goes through the interceptor. There, we validate the request and add the access token, then send the request to the backend server.
After getting the response, the interceptor also handles the response and then sends it to the application.

What is microservice architecture?
-> Microservice architecture means we divide the application into multiple small and independent services. Each service can be developed and deployed independently.
If one service is down, it should not crash the overall application.
I have worked with two patterns: CQRS and Saga pattern.
Currently, I work with the CQRS pattern, where read and write operations are separated into different services.
I have also worked with the Saga pattern, where we create separate services for different modules. For example, in my Wellington Parcel project, we had separate services like Order Service, Tracking Service, and other small services. This makes development and deployment easier.
