70.Have you worked on transactional queries ?
-> So in real-world applications, transaction queries are used to manage data consistency and avoid data loss.

For example, in a payment application, Sender A has ₹1000 in their account and wants to send ₹500 to Sender B. In this case, first ₹500 is deducted from Sender A's account and then that ₹500 is added to Sender B's account.

If the amount is deducted from Sender A's account but while transferring the amount to Sender B, a server issue, network problem, or any other error occurs, then the data becomes inconsistent because the amount is deducted but not credited.

To handle this situation, we use transaction queries. If all operations are completed successfully, we use COMMIT to save the changes. If any error occurs in between, we use ROLLBACK to undo all changes and restore the previous data.

So the main purpose of transaction queries is to maintain data consistency and ensure that either all operations are completed successfully or none of them are applied.

Example :- 

CREATE TABLE sender_a (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    balance DECIMAL(10,2)
);

CREATE TABLE sender_b (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    balance DECIMAL(10,2)
);

INSERT INTO sender_a (name, balance)
VALUES ('Sender A', 1000);

INSERT INTO sender_b (name, balance)
VALUES ('Sender B', 500);


// used transactional queries 

BEGIN;

UPDATE sender_a
SET balance = balance - 500
WHERE id = 1;

UPDATE sender_b
SET balance = balance + 500
WHERE id = 1;

COMMIT;

0.What is the difference between Relational and Non-Relational Databases?

Both relational and non-relational databases are used to store data.

The main difference is how they store and organize data.

In a non-relational database, data is stored in formats such as JSON documents, key-value pairs, graphs, or columns. For example, MongoDB stores data in JSON-like documents.

Relational databases are suitable when data has complex relationships and requires strong consistency, while non-relational databases are suitable for flexible and rapidly changing data structures.

15.What are the types of normalization?
->The main normal forms used in database normalization are:

	1st Normal Form (1NF) – Ensures each column contains atomic values (no multiple values in one column) and each record is unique.
	2nd Normal Form (2NF) – Achieves 1NF and removes partial dependency (non-key attributes depend on the whole primary key).
	3rd Normal Form (3NF) – Achieves 2NF and removes transitive dependency (non-key attributes shouldn’t depend on other non-key attributes).

	1NF → Store data in a single value format and remove repeating data.

	2NF → Remove partial dependency and separate related data into tables.

	3NF → Remove unnecessary dependencies and keep data linked only to the primary key.

	Or even shorter:

	1NF → Remove repeating data.

	2NF → Remove partial dependency.

	3NF → Remove transitive dependency.

53.What are the ACID properties?

->✅ Real-Time ACID Properties (Using Your Words, Improved):

Atomicity :- 
When data is transferred from User A to User B, the full process must complete.
If any step fails, the entire transaction is cancelled — no partial changes happen.

Consistency :- 
After the transaction, the data must stay in a valid state.
There should be no data loss or mismatch during the operation, even if it takes time.

Isolation :- 
Each user's transaction is separate and isolated.
One user’s request should not affect another user’s request, even if they run at the same time.

Durability :- 
Once the entire process is successfully completed, the data is saved permanently in the database — even if the system crashes after that.
